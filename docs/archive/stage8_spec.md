# 段階8 仕様（種族一般化）— v1.0（Sol レビュー反映済み、2026-11-16 ユーザー承認）

権威の階層： 判断は `stage8/PLAN_STAGE8.md` の D8-1〜D8-7（ユーザー承認
済み）。力学の権威は Showdown champions mod（ピン留め commit
`7e743761cd13cdb361fc0f58eb5a866284894f5b`）。実態の根拠は棚卸し4点
（`stage8/inventory_*.md/.csv`、件数突合済み）。本書 v1.0 は Sol の
レビュー（`stage8/spec_review.md`、blocking 2・major 12・minor 2）を
すべて取り込んだもので、指摘番号を各節に併記する。

## 1. 目標と範囲

- 全341種（メガフォルム82＝通常79＋Z 3、ベース種族76種がメガ持ち）を
  同種ミラー1on1で対戦可能にする。技512（未実装444）、特性216（未実装
  213）、持ち物85（未実装52）を実装範囲とする。
- 学習方針の一般化は範囲外（D8-5）。操縦は汎用ヒューリスティクス
  obsh4 まで。
- わるあがき（Struggle）は現行エンジンに表外で実装済みであり、そのまま
  維持する。ただし §11 の通り、表登録とワイヤIDの関係を 8b で明示する。

## 2. 集合の定義（R01）

初期集合と戦闘中の到達可能集合を分ける。

- **初期合法集合**： ビルドが開始時に持ち込めるもの。種族341エントリ、
  初期特性216、技512、持ち物85＋メガストーン81種（82フォルム分）。
- **到達可能集合**： 対戦中に技・特性・フォルム変化で生成されうるもの。
  例： Simple Beam が付与する Simple、ギルガルド／ミミッキュ／ポワルン／
  モルペコ等の戦闘中フォルム、特性の交換・抑制で現れる状態。
  到達可能集合は 8b の前に棚卸しCSVから閉包として列挙し、生成データと
  観測側の語彙に反映する。初期341件へ無条件に追加はしない。
- 「データ上の変身先」と「無交代1on1で実際に到達する状態」（例：
  Palafin-Hero は交代が必要で到達しない）も区別して列挙する。

## 3. 回帰規律（D8-2）

- メタグロスの検証行列 MD5 `f3128c506954574a0c48bdfb79e2a917` は段階8を
  通して両モード不変。一般化はデータ駆動化と機構の追加であり、
  メタグロスの既存対戦の力学・RNG を変えない。
- 既存の監査（verify_6c / verify_6d / verify_7）は各サブステップで
  通し続ける。監査側の許容変更集合の拡張が必要な場合は理由とともに
  記録する。
- 件数の一致は「既存68技・33持ち物・3特性が他種族との相互作用まで
  実装済み」を意味しない。既存語彙の一般化も実装単位に含める（R12）。

## 4. データ駆動化（8b）

### 4.1 コード生成と優先順位（R07）
- エンジンは実行時に JSON を読まない。固定 commit の mod ＋データセット
  から C ヘッダを生成して組み込む。生成は決定的（入力ハッシュ、生成順、
  安定ID）とし、再生成の一致・集合突合・既存PP不変を 8b の受け入れ
  条件にする。
- 項目ごとの権威を固定する： 数値（威力・命中・PP等）は段階6の D5 と
  同じく Serebii Champions 由来のデータセットを第一とし、効果の事実と
  ハンドラは mod を権威とする。差分が出た項目は差分台帳に記録する
  （既知例： Double Shock の命中は dataset null／mod 100 — null を
  必中と解釈しない； Revival Blessing のフラグ差）。
- PP は「実効最大PP」（mod の基礎PPに初期化の20上限と calculatePP を
  通した値）を正とし、二重変換をしない。
- mod の継承規則（`inherit: true`、明示 `undefined` による削除、値形式
  フック）を合成時に解決し、生成物は解決済みの値だけを持つ。

### 4.2 種族表の列（R04 追加分を含む）
- 種族ID、タイプ（元タイプ最大2）、種族値6、**重量（hectogram 単位、
  mod の値）**、特性候補、習得技リスト、フォルム関係（ベース↔メガ／
  Zメガ、必要な石、変身先）。
- 対戦中のタイプは元タイプと別に保持する： 現在タイプ（最大2）＋
  追加タイプ（Forest's Curse／Trick-or-Treat の第3タイプ）＋一時変更
  （Soak、Roost の飛行喪失、Protean 等）と復帰条件を表現できること。
  タイプ参照（相性・STAB・状態免疫・接地・観測）はすべて現在タイプを
  通す。重量も現在値（フォルム・状態で変化）を持つ。

### 4.3 実数値（R03）
- 0ポイント時のコアは一般式で決まる： HP = floor((2×種族値+31)/2)+60
  （＝種族値+75）、その他 = floor((2×種族値+31)/2)+5（＝種族値+20）。
  メタグロスの既存コアと一致することをフィクスチャで確認する。
- **v3 のビルドはポイント配分（各0〜32、合計66ちょうど）と性格を
  保持する**。各形態の最終実数値は「コア＋ポイント→性格補正
  （×110//100・×90//100）」で形態ごとに再計算する。現行の差分方式
  （種族値差が10の倍数前提）は一般化しない（反例： Absol→Mega-Z の
  A下降で 157 対 156 の不一致）。
- 旧スペック（最終実数値のみ）は従来の逆算互換で読み続ける。逆算が
  一意でない旧入力は従来の決定規則に従い、新規生成は v3 形式で行う。

## 5. ビルドスペック文法 v3（R02）

- 正規形は「ベース種族キー＋開始形態の指定」で一意に決める：
  `<base-species>:<points>|<moves>|<policy>|<item>|<mega>|<ability>|<nature>|<sex>`
  - base-species はデータセットのベース種族 id。開始形態は mega
    モードと石で決まる（mega=1 はメガ形態の実数値・特性で開始、
    mega=2 は通常形態で開始し石を保持、mega=0 は変身しない）。
    メガ形態そのものを開始種族に指定する書き方は正規形としない。
  - **性別（sex）を必須欄とする**（m/f/n、種族の性別比に従う合法値
    のみ）。同種ミラーでも Attract／Cute Charm／Rivalry が性別で
    変わるため、型の一部として扱う。雌の通常形態がデータセットに
    ない種族（例： Meowstic）は補助データで表し、雄雌で特性候補が
    異なることを保持する（同じ石 Meowsticite でも変身先が雄雌で
    分かれる）。
  - ability は開始形態（mega=2 なら通常形態）の特性候補のいずれか。
    メガ後の特性はフォルムデータで決まる。
  - 石は item 欄で指定し、対応しない石・メガを持たない種族への
    mega=1/2 は不正として拒否する。旧トークン（none/stone/cb/lm 等）
    と省略欄の扱いは互換表で明示する。
- 「同種ミラー」の判定はベース種族キーの一致で行い、通常対メガ・
  異なる石同士の比較を妨げない。

## 6. 共通ライフサイクル（R05）

実装に先立ち、イベントの時系列を共通基盤として固定する。

- 対戦開始： 両者の登場（SwitchIn/特性 Start）→ 最初の同時観測・選択。
  登場時効果（Intimidate、天候・地形の設置、Imposter 等）はこの順で
  解決する。
- 各ターン： 技とメガの同時宣言 → メガ変身（特性 End/Start を含む）
  → 優先度・素早さの再計算（ModifyPriority も対象）→ 技の実行。
  両者同時メガの解決順もここで固定する。
- 特性の変更・交換・抑制・復帰はすべてこの時系列上のイベントとして
  扱い、既存の技・持ち物も共通フックへ接続する。
- **段階7の「mega=1 と初手 mega=2 の等価性」はメタグロス固有の
  結果であり、一般化しない**。登場効果を持つ種族では両者は一致
  しないのが正しい（例： メガでも Intimidate が再発動する種族）。
  フィクスチャで、初期 Intimidate、同名特性の再起動、両者天候メガ、
  Prankster の喪失／獲得を検証する。

## 7. 技の実装（8c）

大分類（集計用）は棚卸しのグループ分けを引き継ぐが、**実行単位は
D8-6 に合わせてさらに割る**（R12）。各実行単位は「1指示書＋Sol 1実行＋
Muse 独立検証＋コミット」とし、依存関係と完了台帳を
`stage8/units.md` で管理する。分割の原則：

- 共通基盤（§6 の時系列、§4 の表現）が先。次に個別効果、最後に
  後続機構との統合試験。
- 依存の例： Spit Up は Stockpile の後、Fling／Knock Off は持ち物
  移動の後、Transform は特性・フォルム処理の後。
- 未対応の技・特性を成功扱いの no-op として公開しない。未実装は
  明示的に拒否するか、到達不能であることを台帳に記録する。
- Toxic（どくどく）は STATUS の属する単位で、毒タイプの命中無条件
  （命中乱数と半無敵判定の迂回、毒／鋼と特性の免疫は残る）と同時に
  実装する（R16）。

## 8. 特性の実装（8d）

技と同じく大分類は棚卸しを引き継ぎ、実行単位は小さく割る（R12）。
到達可能集合（§2）に現れる特性も対象に含める。`needs_individual` は
72種＋到達可能集合分。未確認の相互作用は §13 の記録規則に従う。

- **へんしん後のフォルムチェンジ（ユーザー裁定、2026-11-17）**:
  第五世代以降の仕様として、へんしんしたポケモンは特性・技・
  持ち物・場の状態などの効果ではフォルムチェンジしない（条件を
  満たしても発動しない）。したがって 8d-4c では「へんしん後に
  自分のメガストーンでメガシンカする」経路は実装しない。
  メガシンカ済みの相手をその姿のまま写すのは写し自体の内容で
  あり、この裁定の対象外（範囲に含める）。mod 側もフォルム変化
  特性（Forecast／Flower Gift／Zen Mode／Schooling／
  Shields Down／Power Construct／Stance Change 等）に
  transformed ガードがあり、この原則と一致する。
- **かわりもの同士のミラー（ユーザー確認、2026-11-17）**:
  両方が Imposter の場合、先に変身した方だけが成功し、後手は
  対象が変身済みのため失敗する（mod の扱いをそのまま採用）。
  先後は 8d-0 のライフサイクルの順序に従い、専用フィクスチャで
  検証する。

## 9. 持ち物の実装

- 未実装52種は棚卸しの11群に割り当て、実行単位と完了条件を
  `stage8/units.md` に置く（R12）。
- **種族専用の補正は、その補正だけを対象種族に限定する**（R06）。
  Light Ball／Leek の能力・急所補正は専用だが、Fling の威力と追加
  効果、持ち物の移動・消費・抑制は一般効果として残る。
- メガストーンの移動禁止は全石一律ではなく、対応種族との組合せで
  判定する（段階7の D7-5 の一般化）。

## 10. 観測 v3 と obsh4（8e）

情報境界の原則は v2 を維持する（D8-4）。種族一般化での境界は次の通り。

- 種族と通常フォルムのタイプ： ミラーでは自明に公開。
- 相手の特性（R08）： 初期合法候補は公開情報。選択そのものは非公開
  だが、**公開メタデータから一意に決まる場合（候補が1つ、公開フォルム
  で特性が一意）は発現なしに確定してよい**（v1 の singleton 規律と
  同じ）。発現イベントは公開され、候補を絞る。戦闘中の変更・交換・
  抑制・復帰は belief の更新として定義し、元の候補へ勝手に戻さない。
  相手の実値を読み戻すことと、ダメージからの数値逆算（R2 で禁止）は
  引き続き禁止。「不発」から候補を削る際は、隠れた持ち物・抑制等の
  別仮説を残す。
- 情報取得の契約（R09）： Frisk（持ち物）・Forewarn（技）のような
  公開は「reveal」であり「use」とは別のイベントとして扱う。PP 消費や
  使用回数と混同しない。Transform でコピーした自分の技・能力値・特性は
  自分の情報として既知だが、コピー元の私有ビルド全体が開示される
  わけではない。コピーした技には相手の未使用の技も含まれ、変身した
  側はその4技を知ったものとして扱う（実ゲームで自分の技欄に見える
  ため。ユーザー確認、2026-11-17）。技集合が変化・増加した場合の
  既知技レコードの保持・
  失効も定義する。Ditto ミラーの Imposter／Transform の先後と失敗
  条件は専用フィクスチャにする。
- 持続時間（R10）： 壁・天候・地形の残りは、公開根拠で一意な場合のみ
  確定値で載せる。未公開の延長持ち物（Light Clay、天候岩、Terrain
  Extender）で 5／8 ターンが分かれる場合は、集合・範囲・経過ターンで
  表し、内部の残り時間を読まない。ランダム持続（拘束等）も同じ分類で
  扱う。同じ公開履歴なら同じ観測になる等価性試験を加える。
- 連続攻撃（R10）： ダメージ記録は「技の使用」と「ヒット」を分けて
  持ち、ヒット数・みがわり破壊・急所・clean 記録の対応を定義する
  （Parental Bond、Triple Axel 等）。A1 の clean 分割の文脈条件が
  一般化できるかもここで確認する。
- エンコーダ（R11）： **内部IDと版別ワイヤIDを 8b で分離する**。
  MGO1／MGO2 は「旧種族・旧語彙・旧初期状態」だけに明示的に
  ルーティングし、対応外は拒否する。v2 の「ID17以上の技を1個必須」
  のような旧条件は引き継がない。MGO3 の詳細レイアウトは 8e で
  設計するが、旧バイト列・旧 pilot・回帰パネルの保護は本書で固定
  したものとする。
- obsh4（R13）： obsh3 の差分評価を種族一般データで動かすことに加え、
  **メガ判断を汎用化する**。判断は「現在の仮説と変身後の仮説の
  差分評価」で行い、相手の未公開の石・特性・宣言は使わない。
  メタグロス専用条件（クリアボディ温存）は一般規則の一例として
  位置づける。

## 11. 探索側の一般化（8e／8f の作業、R13）

- 候補生成・正規化・重複除去を種族一般にする： 種族ごとの習得技、
  配分（§4.3 の v3 形式）・性格・性別、通常特性、石と非メガ持ち物、
  mega モードを canonical identity に含める。現行の
  `campaign3/population.py` と `run3/gen_candidates.py` はメタグロス
  固定であり、そのまま使わない。特に現行 identity が mega≠0 で
  特性を一律に潰す規則は、mega=2 の通常特性の差を消すため廃止する。
- 旧探索資産（run1〜run3 の結果）は固定したまま、新経路を検証する。

## 12. 受け入れ検証（8f、D8-7＋R14）

- D8-7 の4条件（全種族スモーク、ギャラドスの探索＋タイミング検証、
  回帰確認、dist 更新）を維持し、次を加える。
- 検証台帳： 対象ID（技・特性・フォルム・持ち物）→機構→フィクスチャ
  の対応を保持し、各実装単位のフィクスチャは最終受け入れで再実行
  される。「完走」だけを合格としない（no-op でも完走するため）。
- スモークは全82メガフォルムの変身先・81種の石・Z 3種を含む合法
  ビルドで、通常／メガ開始の両モードと左右入替を固定 seed で回す。
- 観測の等価性（観測ON/OFFで結果・ターン・RNG・状態が一致）、
  マスク同値、両者選択の凍結など、段階6c の検証資産を一般化して
  適用する。obsh4 が使わない効果もスクリプト指定の行動で検証する。
- ギャラドスのタイミング比較は、段階7と同型のプローブ（即メガ対照
  vs タイミング判断）で、再現条件（seed・試合数・母集団）を事前に
  固定する。

## 13. 記録の規則（R15）

- 力学の値は3層に分けて記録する： 固定 mod の値／プロジェクトの裁定
  （ユーザー裁定済みの例外は維持する。例： Steel Beam 同時KO は
  ユーザーの負け）／実ゲームでは未確認の事項。
- mod 値で実装し、実測未確認の点は注記する（例： Aura Guard の
  breakable は mod 値 true で実装し、TODO は未確認として残す）。
  新しい例外判断が必要な場合だけ ask-first でユーザーに聞く。

## 14. 未確定事項（期限つき）

- 到達可能集合の閉包リストの確定： 8b の前（§2）。
- MGO3 の詳細レイアウト： 8e（§10 の境界は本書で確定）。
- 1on1 で部分的に意味を持つ技・特性の線引き（U-turn は攻撃部分が
  残る、Chilly Reception は天候が残る、Illusion は単独編成では
  外見候補なし、Zero to Hero は無交代では起動しない等）は、棚卸しの
  確認済み事項を取り込み、曖昧なケースだけ個別に確定する。
  技・特性を丸ごと無効化する規則にはしない。
