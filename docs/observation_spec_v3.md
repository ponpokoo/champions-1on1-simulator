# 段階8e 仕様（観測 v3／MGO3＋obsh4＋探索側の一般化）— v1.0

状態: 確定（2026-11-18）。v0.9 ドラフトの唯一の未決事項だった
D8e-1（可能性集合の符号化粒度）は、ユーザーの指摘
（「持ち物も技も実数値もある程度は絞られる」）を受けて
§3.8 のとおり全要素に可能性集合と区間を持つ形で確定した。
上位文書: `stage8/SPEC_STAGE8.md`（特に §10 の R08〜R13、§11）、
`stage6/OBSERVATION_SPEC_V2_DRAFT.md`（v2 仕様、裁定 R1〜R5 と Amendment A1）。

## 1. 目標と範囲

- 観測スキーマ v3（輸送名 MGO3）を設計・実装し、種族一般の対戦で
パイロットが使える観測にする。
- ヒューリスティクス obsh4 を obsh3 の後継として実装する
（種族共通の差分評価＋一般化したメガ判断）。
- 探索側（候補生成・identity・screen 配線）を種族一般化する。
- 学習方針の一般化は範囲外（D8-5: 段階8の完了条件ではない）。
- 回帰規律: MGO1／MGO2 と旧 pilot は凍結。検証行列の MD5
`f3128c506954574a0c48bdfb79e2a917` は両モードとも不変（D8-2）。

## 2. 原則（v2 から不変）

- 中核不変条件: 自分の状態と公開履歴が同じなら、相手の隠れた状態に
よらず観測とマスクは同一になる。相手のエンジン実値は決して
コピーしない。各フィールドは exact（自分）／public-event／
belief（許された証拠だけからの決定的関数）のいずれか。
- R1（計算可能なら知り得る）、R2（見たダメージ記録は入れる、
正確な実数値の逆算は入れない）、R3（ランダムな持続は経過のみ）、
R4・R5（公開失敗の扱い）はそのまま引き継ぐ。
- SPEC §10 の適用: 特性の初期合法候補は公開情報（R08）、
reveal は use と別イベント（R09）、持続は公開根拠で一意な
場合のみ確定値（R10）、内部 ID と版別ワイヤ ID の分離（R11）、
obsh4 のメガ判断は公開情報だけの仮説差分（R13）。

## 3. MGO3 のフィールド棚卸し（v2 からの差分）

v2 の全フィールドは引き継ぐ（自分の状態、公開イベント列、
公開された技のレコード、見たダメージ記録、場の基本要素、
試行結果の分類など）。以下は v3 で新たに加わるものと、
一般化されるものだけを挙げる。正確な幅と並びは 8e-2 の
実装指示書で凍結する（v2 と同じ運用）。

### 3.1 同一性（種族・フォルム・タイプ）

- 自分の種族・現在フォルム・現在タイプ: exact。
- 相手の種族・通常フォルム: public（対戦開始時に公開される）。
現在フォルムと現在タイプは public-event／belief
（フォルム変化・タイプ変化の技と特性は公開イベントとして
再生する。タイプ変更の履歴そのものではなく現在の値を持つ）。
- ワイヤ ID は 8b の種族テーブル（351行）に基づく版別 ID を使う。

### 3.2 特性

- 自分の特性と状態（変更・抑制・復帰）: exact。
- 相手の特性: 公開イベントで確定した場合はその同一性。
未確定の場合は候補集合の扱いが D8e-1 に従う（§3.8）。
変更・交換・抑制・復帰は belief の更新として定義し、
元の候補へ勝手に戻さない（R08）。
- 「不発」から候補を削るときは、隠れた持ち物・抑制などの
別仮説が残る形にし、決定的な公開証拠がある場合だけ削る（R08）。

### 3.3 持ち物

- 自分の持ち物と状態: exact。
- 相手の持ち物: 公開イベント（Frisk 等の reveal、消費・喪失・
交換・復元の公告）で確定した同一性と状態だけを載せる。
未公開の持ち物の実値は載せない。候補集合の扱いは D8e-1 に従う。
- reveal は use とは別のイベントとして区別する（R09）。

### 3.4 技と見たダメージ記録の一般化

- 技の語彙は 512（ワイヤ ID は版別 ID、Struggle は特殊行動のまま）。
公開された技のレコード構造は v2 を引き継ぎ、語彙だけ広げる。
- 見たダメージ記録（R2＋A1 の clean 分割）は種族一般に拡張する:
公開された技ごとに、直接ヒットの min／max（全体と clean）、
ヒット数、急所ヒット数、みがわりヒットは件数＋破壊フラグのみ。
- **多段ヒットの帰属（R10 の一般化）**: ダメージ記録は「技の使用」と
「ヒット」を分けて持つ。連続技（Triple Axel 等）と Parental Bond は、
ヒット単位のバーの端点をヒット順に帰属させ、使用単位の集計とは
別に持つ。帰属できない端点（残留・反動・回復・天候）は v2 と
同様に記録へ入れない。
**保持範囲（ユーザー裁定、2026-11-18）**: ヒット端点の記録は
その技の全ての使用にわたる累計の要約（min／max・件数）として
持つ。直近の使用だけに限らない。端点の列そのものは保持しない
（v2 の見たダメージ記録と同じ要約の形）。
- 技集合が変化・増加した場合（Transform、Sketch 等）の既知技
レコードの保持・失効を定義する（R09）。Transform でコピーした
技は自分の情報として既知（SPEC §10 の裁定どおり）。

### 3.5 場と揮発状態

- 場: 天候・地形（4種）・壁（両側）・設置物（両側）・
トリックルーム等のルーム系・しっぽ風など、8c で実装された
場の要素すべてを公開イベント＋導出で載せる。
- 揮発状態: 8c／8d で実装された到達可能な集合全体を、
公開イベントと経過ターン（R3）で載せる。v2 で省略した
ものの扱い（対戦境界に残らない内部状態は載せない）は維持する。

### 3.6 メガとへんしん

- 自分: メガ済みかどうか、mega=2 の未使用かどうか、自分の石は
exact。相手: メガシンカの実行は公開イベント。相手がまだ
メガし得るかは belief（種族にメガフォルムがあり、未実行で
あることだけ。石の有無そのものは読まない）。二重メガ種族では
候補フォルムを belief として区別する。
- へんしん: 変身した事実は公開イベント。変身した側にとって
コピーした技・能力値・特性は自分の情報（exact 側）。
変身された側からは、相手が変身したことと公開された範囲だけ。

### 3.7 持続時間の表現（R10）

- 公開根拠で一意に定まる持続: 確定値（v2 の導出と同じ）。
- 未公開の延長持ち物で 5／8 ターンに分かれる場合: 確定値では
なく、候補の集合（範囲）＋経過ターンで表す。内部の残り時間を
読まない。ランダム持続も同じ分類（経過のみ、R3）。
- 等価性試験: 同じ公開履歴なら同じ観測になることを、隠れた
延長持ち物の有無を変えたペアで確認する（8e-2 の受け入れ）。

### 3.8 可能性集合と実数値区間（D8e-1、確定）

相手の未公開要素は、公開データと公開イベントから計算可能な
**候補集合**として belief で載せる。絞り込みは「発動した」
イベントだけでなく「発動しなかった」事実からも進む
（ユーザー指摘、2026-11-18: 持ち物も技も実数値もある程度は
絞られる）。対象は次の4種で、いずれも公開情報だけからの
決定的な計算であり、実値のコピーはしない。

- **特性**: 種族の合法候補から、決定的な公開証拠で否定できる
  ものを除いた集合（発現イベント、「発動するはずの場面で
  発動しなかった」事実。ただし隠れた持ち物・抑制等の別仮説が
  残る場合は削らない、R08）。
- **持ち物**: 合法候補から公開証拠で否定できるものを除いた
  集合。絞り込みの根拠の例: ターン終了時に回復しなかった
  （食べ残し等の否定）、攻撃後に反動がなかった（命の珠の否定）、
  HP が発動境界を下回っても発動しなかった（回復実・半減実の
  否定）、素早さの前後関係（スカーフ等の否定・確定）、
  ダメージの大きさ（半減実・補正持ち物の否定）。公開イベントで
  確定した場合は集合ではなく同一性と状態を載せる（§3.3）。
  **母集団と輸送（D8e-2、2026-11-18 ユーザー裁定）**: 持ち物の
  候補の母集団は、通常持ち物85種に「持ち物なし」と、その種族に
  対応するメガストーン（生成表のメガ対応の順、最大2種）を
  加えたものとする。輸送は持ち物ブロック（920..923、4ワード）の
  未使用ビットに載せる: valid、85種（生成表の順）、「なし」、
  対応ストーンの順に並べ、残りのビットはゼロのままにする。
  配置（ブロックの開始オフセットと幅）は変えない。「なし」と
  対応ストーンも除外規則の対象であり、メガシンカの公開発生は
  対応ストーンへの収束、持ち物の公開使用・消費・公開は
  「なし」とストーンの除外になる。健全な除外では候補が全て
  消えることはなく、空集合は到達しない状態として扱う
  （フィクスチャで到達しないことを確認する）。
- **技**: 未公開の技スロットについて、種族の習得可能技から
  公開済みの技と公開証拠で否定できるものを除いた集合。
  公開された技は同一性として既知（§3.4）。
- **実数値**: 相手の6能力について、公開されたバーの端点と
  公開文脈（乱数幅85〜100、急所の有無、ランク・壁・天候等の
  公開補正）および素早さの前後関係から計算可能な
  **[下限, 上限] の区間**を belief として載せる。点値は
  決して載せない。区間は公開履歴の追加で狭まることはあっても
  広がることはない。
  **区間の対象と能力値変更時の更新（D8e-3、2026-11-18
  ユーザー裁定）**: 区間は相手の**現在の**実数値を追跡する。
  メガシンカ・フォルムチェンジ・変身・能力値の交換など、
  対象値そのものが公開イベントで変わる場合、変化前の区間が
  表す配分・性格の制約集合は破棄されず、その集合を新しい
  フォルム（新しい対象値）の実数値計算式に決定的に写像して
  新しい区間とする。したがって、例えばメガ前に確定した
  下限の判断は、メガ後も制約として生き続け、写像後の区間を
  狭める。「狭まることはあっても広がることはない」という
  単調性は、同一の対象値（同一フォルムの同一能力）を追跡
  する期間内に適用される。
  これは v2 の R2（正確な実数値の逆算は入れない）の v3 での
  改定である: 点値の逆算は引き続き禁止し、代わりに区間を
  符号化する。見たダメージ記録（§3.4）は引き続き併記し、
  区間はその記録と公開文脈から決定的に導かれるものとする。

幅の目安: 特性候補 217bit、持ち物候補 85bit、技候補 512bit、
実数値区間 6能力×2境界。いずれも §4 の上限に収まる。

## 4. 輸送形式

- MGO3: 固定幅、**1024 ワード上限**（v1: 256、v2: 512 の倍化の流れ）。
カテゴリには明示的なタグと有効ビットを持たせ、
unknown ≠ zero ≠ absent の区別は v1／v2 の規律を引き継ぐ。
- MGO1／MGO2 は旧種族・旧語彙・旧初期状態だけに明示的に
ルーティングし、対応外は拒否する（R11）。v2 の旧条件
（ID17以上の技を1個必須など）は引き継がない。
- エンコーダは公開イベント列からの再生で構築し、相手の `Mon` や
対戦の `FIELD` の生状態からのコピーを禁止する（v2 の禁止条項）。

## 5. obsh4 の設計要件

- MGO3 と行動マスクだけの純粋関数（obsh3 と同じ契約）。
隠れた状態へのアクセスと乱数は禁止。
- 差分評価の一般化: 期待ダメージと状態異常の価値づけを、
8b の種族テーブル（実数値計算・タイプ相性・現在タイプ）から
組み立てる。種族固有の定数は持たない。見たダメージ記録は
公開仮説の範囲で使ってよい（v2 の obsh3 と同じ境界）。
- メガ判断の一般規則（R13）: 「今メガする仮説」と「しない仮説」の
差分評価を公開情報だけで比較する。相手の未公開の石・特性は
使わない。段階7の obsh3 規則（発動条件が到達不能だった）の
反省として、規則の到達可能性をフィクスチャで確認する。
- 評価の物差し: 宣言した相手分布に対する期待勝率が主、
最悪相性が副（プロジェクトの主問いと同一）。

## 6. 探索側の一般化

- identity: 種族・配分・性格・性別・特性・持ち物（石を含む）・
mega モードを canonical identity に含める。現行の
「mega≠0 で特性を一律に潰す」規則は廃止する（SPEC §11）。
- 候補生成: 種族テーブルに基づき種族パラメータ化する
（習得技・性別の合法性・特性候補・石の対応は 8b の生成
テーブルが正）。正規化と重複除去も種族一般にする。
- screen／screenx のパイロット配線を obsh4 に接続する。
- 旧探索資産（run1〜run3 の結果）は固定したまま、新経路を検証する。

## 7. 単位分割と受け入れの骨子

- **8e-1 仕様**: 本書の v1.0 確定（D8e-1 の裁定を含む）。
- **8e-2a 符号化器（本体）**: MGO3 エンコーダの同一性・場・状態の
符号化。受け入れ: 等価性試験（隠れた状態を変えたペアで観測が
バイト同一）、§3.7 の延長持ち物ペア、MGO1／MGO2 の回帰
（行列 MD5 不変、v2 パネルの再現）、メタグロス範囲での
v2 との判断比較。
- **8e-2b 符号化器（belief）**: §3.8 の候補集合（特性・持ち物・
技）と実数値区間の計算。受け入れ: 除外規則ごとの等価性ペア
（同じ公開履歴なら同じ観測）、区間の単調性（狭まることは
あっても広がらない）、点値が決して載らないことの確認。
除外の根拠が曖昧な規則は実装で決めずユーザーに諮る。
- **8e-3 obsh4**: 実装と対照評価。受け入れ: run3 のファイナリスト
母集団（メタグロスミラー、宣言分布は強型メタ）で obsh3 と
対照し、期待勝率で大きく劣らないこと（閾値は指示書で
CI を見て固定する）。メガ規則の到達可能性フィクスチャ。
- **8e-4 探索側**: identity 解消＋候補生成の種族パラメータ化＋
screen 配線。受け入れ: 複数種族での候補生成とスクリーニングの
スモーク（8f の全種族スモークとは別に、小規模でよい）。

## 8. 決裁ログ

- 確定済み（上位文書より）: D8-4（情報境界は v2 の原則を維持）、
D8-5（学習方針の一般化は完了条件ではない）、R1〜R5、A1、
R08〜R13 の適用方針。
- D8e-1（確定、ユーザー、2026-11-18）: 可能性集合は特性・
  持ち物・技の全要素に持ち、実数値は区間で持つ（§3.8）。
  v2 の R2 は「点値の逆算は禁止、区間は符号化可」の形に改定。

- D8e-2（確定、ユーザー、2026-11-18）: 持ち物 belief の母集団に
  「持ち物なし」と種族対応メガストーン（最大2種）を含め、
  持ち物ブロック（920..923）の未使用ビットに載せる（案A）。
  詳細は §3.8。

- D8e-3（確定、ユーザー、2026-11-18）: 実数値区間は現在の
  値を追跡する。公開された能力値変更（メガシンカ・フォルム
  チェンジ・変身・能力値交換等）では、変化前の区間が表す
  配分・性格の制約集合を引き継ぎ、新しいフォルムの計算式に
  写像して区間を作り直す。単調性は同一の対象値を追跡する
  期間内で適用する。詳細は §3.8。
