# 観測仕様 v3（MGO3 / obsh4 / 種族一般化）

> **適用範囲**: 全 341 種族の同種ミラー対戦における観測インターフェース（輸送形式 `MGO3`）、ヒューリスティクス方針 `obsh4`、および探索側の種族一般化仕様。  
> **関連文書**: 開発時の段階仕様・下位仕様は [docs/archive/stage8_spec.md](archive/stage8_spec.md) および [docs/archive/observation_spec_v2.md](archive/observation_spec_v2.md) を参照。

## 1. 目標と範囲

- 観測スキーマ v3（輸送名 `MGO3`）を定義し、全種族一般の対戦で操縦方針が使える観測を提供する。
- ヒューリスティクス `obsh4` を `obsh3` の後継として提供する（種族共通の差分評価＋一般化したメガ判断）。
- 探索側（候補生成・同一性判定・`screen` 配線）を種族一般化する。
- 学習方針（PPO）の全種族一般化は本仕様の範囲外（学習パイプライン [training/](../training/README.md) は v1 / `MGO1` 専用）。
- 回帰規律：`MGO1` / `MGO2` と旧方針は凍結し、検証マトリクス（`matrix 3000 12345`）の MD5 `f3128c506954574a0c48bdfb79e2a917` は観測 OFF / 互換 ON の両モードとも不変とする。

## 2. 原則（v2 から継承）

- **中核不変条件**：自分の状態と公開履歴が同じなら、相手の隠れた状態によらず観測と合法行動マスクは同一になる。相手のエンジン実値は決してコピーしない。各フィールドは `exact`（自分）／`public-event`（公開事象）／`belief`（許された証拠だけからの決定的関数）のいずれかとする。
- v2 の裁定 R1（計算可能なら知り得る）、R2（見たダメージ記録は入れるが、点値の逆算は入れない — §3.8 で区間表現へ改定）、R3（ランダムな持続は経過のみ）、R4・R5（公開失敗の扱い）を引き継ぐ。
- 特性の初期合法候補は公開情報とし、公開トリガー（Frisk 等の `reveal`）と技の `use` は別イベントとして扱う。持続時間は公開根拠で一意な場合のみ確定値とし、メガ判断は公開情報のみの仮説差分で行う。

## 3. MGO3 のフィールド仕様（v2 からの差分）

v2 の全フィールド（自分の状態、公開イベント列、公開された技のレコード、見たダメージ記録、場の基本要素、試行結果の分類など）を引き継ぎ、以下を追加・一般化する。実装は [engine/engine.c](../engine/engine.c) の `Observation3`（1,024 ワード固定長）にある。

### 3.1 同一性（種族・フォルム・タイプ）

- 自分の種族・現在フォルム・現在タイプ：`exact`。
- 相手の種族・通常フォルム：`public`（対戦開始時に公開される）。現在フォルムと現在タイプは `public-event` / `belief`（フォルム変化・タイプ変化の技と特性は公開イベントとして再生する。タイプ変更の履歴そのものではなく現在の値を持つ）。
- ワイヤ ID は [engine/stage8/species_data.h](../engine/stage8/species_data.h) の種族テーブル（351 行）に基づく版別 ID を使う。

### 3.2 特性

- 自分の特性と状態（変更・抑制・復帰）：`exact`。
- 相手の特性：公開イベントで確定した場合はその同一性。未確定の場合は候補集合の扱いが §3.8（D8e-1）に従う。変更・交換・抑制・復帰は belief の更新として定義し、元の候補へ勝手に戻さない。
- 「不発」から候補を削るときは、隠れた持ち物・抑制などの別仮説が残る形にし、決定的な公開証拠がある場合だけ削る。

### 3.3 持ち物

- 自分の持ち物と状態：`exact`。
- 相手の持ち物：公開イベント（Frisk 等の reveal、消費・喪失・交換・復元の公告）で確定した同一性と状態だけを載せる。未公開の持ち物の実値は載せない。候補集合の扱いは §3.8 に従う。
- `reveal` は `use` とは別のイベントとして区別し、PP 消費や使用回数と混同しない。

### 3.4 技と見たダメージ記録の一般化

- 技の語彙は 512（511 技＋わるあがき。ワイヤ ID は版別 ID、Struggle は特殊行動のまま）。公開された技のレコード構造は v2 を引き継ぎ、語彙だけ広げる。
- 見たダメージ記録（R2＋A1 の clean 分割）は種族一般に拡張する：公開された技ごとに、直接ヒットの min / max（全体と clean）、ヒット数、急所ヒット数、みがわりヒットは件数＋破壊フラグのみ。
- **多段ヒットの帰属**：ダメージ記録は「技の使用」と「ヒット」を分けて持つ。連続技（Triple Axel 等）と Parental Bond は、ヒット単位のバーの端点をヒット順に帰属させ、使用単位の集計とは別に持つ。帰属できない端点（残留・反動・回復・天候）は記録へ入れない。
- **保持範囲（2026-11-18 裁定）**：ヒット端点の記録はその技の全ての使用にわたる累計の要約（min / max・件数）として持つ。直近の使用だけに限らず、端点の列そのものは保持しない。
- 技集合が変化・増加した場合（Transform、Sketch 等）の既知技レコードの保持・失効を定義する。Transform でコピーした技は自分の情報として既知とする（実ゲームで自分の技欄に見えるため）。

### 3.5 場と揮発状態

- 場：天候・地形（4 種）・壁（両側）・設置物（両側）・トリックルーム等のルーム系・おいかぜなど、エンジンで実装された場の要素すべてを公開イベント＋導出で載せる。
- 揮発状態：1on1 到達可能集合全体を、公開イベントと経過ターン（R3）で載せる（対戦境界に残らない内部状態は載せない）。

### 3.6 メガシンカとへんしん

- 自分：メガ済みかどうか、`mega=2` の未使用かどうか、自分の石は `exact`。相手：メガシンカの実行は公開イベント。相手がまだメガし得るかは `belief`（種族にメガフォルムがあり、未実行であることだけ。石の有無そのものは読まない）。二重メガ種族では候補フォルムを `belief` として区別する。
- へんしん：変身した事実は公開イベント。変身した側にとってコピーした技・能力値・特性は自分の情報（`exact` 側）。変身された側からは、相手が変身したことと公開された範囲だけが見える。

### 3.7 持続時間の表現

- 公開根拠で一意に定まる持続：確定値。
- 未公開の延長持ち物（ひかりのねんど、天候岩、グランドコート等）で 5 / 8 ターンに分かれる場合：確定値ではなく、候補の集合（範囲）＋経過ターンで表し、内部の残り時間を読まない。ランダム持続も同じ分類（経過のみ、R3）とする。

### 3.8 可能性集合と実数値区間（D8e-1〜D8e-3）

相手の未公開要素は、公開データと公開イベントから計算可能な**候補集合**として belief で載せる。絞り込みは「発動した」イベントだけでなく「発動しなかった」事実からも進む。対象は次の 4 種で、いずれも公開情報だけからの決定的な計算であり、実値のコピーはしない。

- **特性**：種族の合法候補から、決定的な公開証拠で否定できるものを除いた集合（発現イベント、「発動するはずの場面で発動しなかった」事実。ただし隠れた持ち物・抑制等の別仮説が残る場合は削らない）。
- **持ち物**：合法候補から公開証拠で否定できるものを除いた集合。絞り込みの根拠の例：ターン終了時に回復しなかった（食べ残し等の否定）、攻撃後に反動がなかった（命の珠の否定）、HP が発動境界を下回っても発動しなかった（回復実・半減実の否定）、素早さの前後関係（スカーフ等の否定・確定）、ダメージの大きさ（半減実・補正持ち物の否定）。公開イベントで確定した場合は集合ではなく同一性と状態を載せる（§3.3）。
  - **母集団と輸送（D8e-2）**：持ち物の候補の母集団は、通常持ち物 85 種に「持ち物なし」と、その種族に対応するメガストーン（生成表のメガ対応の順、最大 2 種）を加えたものとする。輸送は持ち物ブロック（920..923、4 ワード）の未使用ビットに載せる：`valid`、85 種（生成表の順）、「なし」、対応ストーンの順に並べ、残りのビットはゼロのままにする。メガシンカの公開発生は対応ストーンへの収束、持ち物の公開使用・消費・公開は「なし」とストーンの除外になる。健全な除外では候補が全て消えることはなく、空集合は到達しない状態として扱う。
- **技**：未公開の技スロットについて、種族の習得可能技から公開済みの技と公開証拠で否定できるものを除いた集合。公開された技は同一性として既知（§3.4）。
- **実数値**：相手の 6 能力について、公開されたバーの端点と公開文脈（乱数幅 85〜100、急所の有無、ランク・壁・天候等の公開補正）および素早さの前後関係から計算可能な **[下限, 上限] の区間** を belief として載せる。点値は決して載せない。区間は公開履歴の追加で狭まることはあっても広がることはない。
  - **区間の対象と能力値変更時の更新（D8e-3）**：区間は相手の**現在の**実数値を追跡する。メガシンカ・フォルムチェンジ・変身・能力値の交換など、対象値そのものが公開イベントで変わる場合、変化前の区間が表す配分・性格の制約集合は破棄されず、その集合を新しいフォルム（新しい対象値）の実数値計算式に決定的に写像して新しい区間とする。「狭まることはあっても広がることはない」という単調性は、同一の対象値（同一フォルムの同一能力）を追跡する期間内に適用される。
  - これは v2 の R2（正確な実数値の逆算は入れない）の v3 での改定である：点値の逆算は引き続き禁止し、代わりに区間を符号化する。見たダメージ記録（§3.4）は引き続き併記し、区間はその記録と公開文脈から決定的に導かれるものとする。

幅の目安：特性候補 217bit、持ち物候補 85bit（＋なし・対応石）、技候補 512bit、実数値区間 6 能力×2 境界。いずれも §4 の上限に収まる。

## 4. 輸送形式

- `MGO3`：固定幅、**1,024 ワード上限**（v1: 256、v2: 512 の倍化の流れ）。カテゴリには明示的なタグと有効ビットを持たせ、`unknown != zero != absent` の区別は v1 / v2 の規律を引き継ぐ。
- `MGO1` / `MGO2` は旧種族・旧語彙・旧初期状態だけに明示的にルーティングし、対応外は拒否する。v2 の旧条件（ID17 以上の技を 1 個必須など）は引き継がない。
- エンコーダは公開イベント列からの再生で構築し、相手の `Mon` や対戦の `FIELD` の生状態からのコピーを禁止する。

## 5. obsh4 の設計要件

- `MGO3` と行動マスクだけの純粋関数（`obsh3` と同じ契約）。隠れた状態へのアクセスと乱数は禁止。
- **差分評価の一般化**：期待ダメージと状態異常の価値づけを、種族テーブル（[engine/stage8/species_data.h](../engine/stage8/species_data.h)：実数値計算・タイプ相性・現在タイプ）から組み立てる。種族固有の定数は持たない。見たダメージ記録は公開仮説の範囲で使ってよい。
- **メガ判断の一般規則**：公開情報だけで「今メガする仮説」と「しない仮説」の差分評価を比較する。相手の未公開の石・特性は使わない。
- **評価の物差し**：宣言した相手分布に対する期待勝率が主、最悪相性が副（プロジェクトの主問いと同一）。

## 6. 探索側の一般化

- **同一性判定（identity）**：種族・配分・性格・性別・特性・持ち物（石を含む）・メガモードを正規キーに含める（[search/population3.py](../search/population3.py) の `identity()`）。メタグロス専用の旧規則（`mega != 0` で特性を一律に潰す扱い）は廃止済み。
- **候補生成**：種族テーブルに基づき種族パラメータ化する（習得技・性別の合法性・特性候補・石の対応は `engine/stage8/species_data.h` および `search/population3_catalog.c` が正）。正規化と重複除去も種族一般にする。
- `screen` / `screenx` のパイロット配線を `obsh4` に接続する（`search/search_tiers.py` / `search/search_controller.py`）。

## 7. 検証要件（受け入れ不変条件）

- **等価性試験**：隠れた状態（未公開の持ち物・延長持ち物の有無・未公開の能力値など）を変えたペアでも、公開履歴が同一であれば `MGO3` の観測はバイト同一になること。
- **信念の健全性**：除外規則ごとの等価性、実数値区間の単調性（同一フォルム追跡中に広がらないこと）、点値が直接載らないこと、健全な除外で持ち物・特性・技の候補集合が空にならないこと。
- **回帰確認**：`MGO1` / `MGO2` の回帰（`matrix 3000 12345` の MD5 `f3128c506954574a0c48bdfb79e2a917` が観測 OFF / 互換 ON ともに不変）。
- **方針と探索の動作確認**：`obsh4` のメガ判断が到達可能であること、複数種族（全 341 種族およびメガ形態）で合法な候補生成と対戦が異常終了しないこと。

## 8. 決裁ログ

- **継承済み**：`D8-4`（情報境界は v2 の原則を維持）、`D8-5`（学習方針の一般化は段階 8 の完了条件ではない）、`R1`〜`R5`、`A1`、`R08`〜`R13`。
- **D8e-1（確定、2026-11-18）**：可能性集合は特性・持ち物・技の全要素に持ち、実数値は区間で持つ（§3.8）。v2 の R2 は「点値の逆算は禁止、区間は符号化可」の形に改定。
- **D8e-2（確定、2026-11-18）**：持ち物 belief の母集団に「持ち物なし」と種族対応メガストーン（最大 2 種）を含め、持ち物ブロック（920..923）の未使用ビットに載せる（§3.8）。
- **D8e-3（確定、2026-11-18）**：実数値区間は現在の値を追跡する。公開された能力値変更（メガシンカ・フォルムチェンジ・変身・能力値交換等）では、変化前の区間が表す配分・性格の制約集合を引き継ぎ、新しいフォルムの計算式に写像して区間を作り直す。単調性は同一の対象値を追跡する期間内で適用する（§3.8）。
