# 型スペックと CLI リファレンス

エンジン（`engine/engine.c`）に渡す型スペックの文法と、コマンドラインの
使い方をまとめる。探索の進め方は `skill/SKILL.md` と `search/README.md`、
情報制約は `docs/observation_spec.md`（v1）/ `docs/observation_spec_v2.md`（v2）/
`docs/observation_spec_v3.md`（v3）を参照。

## 1. 型スペックの文法（v3・現行）

1行が1つの型を表す。全種族共通の正規形は次のとおり。

```
<種族>:<ポイント配分>|<技>|<方針>|<持ち物>|<メガ>|<特性>|<性格>|<性別>
```

例（ギャラドスの探索で決勝1位になった型）:

```
gyarados:14,7,0,7,6,32|fireblast,powerwhip,rest,roar|obsh4|gyaradosite|2|intimidate|4,1|f
```

### 種族とポイント配分

- 種族は `data/species_dataset.json` のベース種族 id（英語小文字）。
  対応は実装済みの全341種族。メガ形態そのものを種族に指定する書き方は
  正規形ではない（メガは持ち物とメガ欄で表す）。
- ポイント配分は H,A,B,C,D,S の順に6つの数値（各0〜32、合計ちょうど66）。
  実数値への換算は、フォルムごとの基礎値（ポイント0・個体値31）に
  ポイントを加え、最後に性格補正（上昇 ×1.1、下降 ×0.9、いずれも切り捨て）を
  掛ける。基礎値はデータセットと `engine/stage8/species_data.h` を参照。

### 技

- 4つの異なる技を、英語小文字の技 id で書く（例: `earthquake`）。
  各種族の習得技はデータセットを参照。技の数値はチャンピオンズ仕様。

### 方針（操縦役）

**誰が操縦するかで型の評価は変わる**ため、結果には必ず方針を併記すること。

| トークン | 内容 |
|---|---|
| obsh4 | 観測 v3 のヒューリスティクス方針（全種族・現行の標準） |
| obsh3 | 観測 v2 のヒューリスティクス方針（メタグロス68技用） |
| learned / learned2 | 学習方針（観測 v1 / v2。68技では対照超え未確認） |
| obsh2 | 観測 v1 のヒューリスティクス方針（17技用） |
| mirror / noise / fast / stall | 単純方針（検証マトリクス等） |
| generic | 全情報ベースライン（比較用と明示した場合のみ使う） |

### 持ち物・メガ・特性・性格・性別

- 持ち物は英語小文字の id（例: `leftovers`, `lifeorb`、メガストーンは
  `gyaradosite` のような種族ごとの id、なしは `none`）。実装済みは85種。
- メガ欄は `0`（変身しない）/ `1`（メガ形態で開始）/ `2`（通常形態で開始し、
  石を保持。メガシンカの宣言タイミングは方針が決める）。対応しない石や
  メガを持たない種族への `1` / `2` は不正として拒否される。
  なお標準の評価前提は1ターン目メガであり、その根拠と種族別の検証手順は
  `search/README.md` を参照。
- 特性は開始形態の特性候補のいずれか（英語小文字 id）。実装済みは217種。
  メガ後の特性はフォルムデータで決まる。
- 性格は `上昇,下降` の2つの数値で、1=攻撃、2=防御、3=特攻、4=特防、
  5=素早さ、無補正は `0,0`。HPに性格補正は掛からない。
- 性別は `m` / `f` / `n`（種族の性別比に従う合法値のみ必須）。
  めろめろ・ゆうわく・とうそうしん等が性別で変わるため型の一部として扱う。

### 旧形式（メタグロス専用・互換）

段階6までのメタグロス専用形式
`実数値6つ|技コード|方針|アイテム|メガ|特性` も読み取り互換がある
（例: `164,192,182,113,132,162|FS,IW,ST,EQ|obsh3|stone|1|cb`）。
新規の型は v3 形式で書くこと。

## 2. CLI リファレンス

ビルドは `make verify`（または `gcc -O3 -march=native -o engine/engine engine/engine.c -lm`）。
以下、`<engine>` は `engine/engine` と読み替える。

| コマンド | 引数 | 出力 |
|---|---|---|
| `policy-version` | なし | 方針ごとの観測スキーマと重みハッシュ（1方針1行） |
| `matrix` | `[試合数] [シード]` | 検証マトリクス（既定 3000 / 12345）。MD5 が `engine/fixtures/expected_matrix_md5.txt` と一致することが導入セルフチェック |
| `battle` | `<型A> <型B> <試合数> <シード>` | 「A 勝ち数 - B 勝ち数（引分数）平均ターン数」 |
| `screen` | `<候補ファイル> <プールファイル> <試合数> <シード>` | 候補ごとに「番号 勝 敗 分」を1行ずつ（プール全員との合計） |
| `screenx` | `<候補ファイル> <プールファイル> <試合数> <シード>` | 候補ごとに「番号」に続けてプール1人ごとの「勝 敗 分」を1行で。実行中は進捗が標準エラーに流れる |
| `trace` | `<型A> <型B> <シード>` | 1試合の詳細ログ（全情報方針同士のみ。観測系方針では使えない） |

### 使い方の注意

- スコア規約は **勝 /（勝+敗+分）**。結果には常に対戦母集団・試合数・操縦方針・
  シードを併記すること。
- `screen` / `screenx` では候補は常に **A 席** に座る。席による差をならす必要がある
  評価（決勝など）では、候補とプールを入れ替えた実行も行い、両席を併せること。
- 平均勝率だけでなく **最悪相性**（プール内で最も低い相手別スコア）も必ず見ること。
  相手別の内訳は `screenx` で得られる（`screen` の合計だけでは最悪相性は分からない）。
- シードは試合ごとにハッシュで展開される決定的な規約で、同じ引数なら結果は再現する。
