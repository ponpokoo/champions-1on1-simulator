# 型スペックと CLI リファレンス

エンジン（`engine/engine.c`）に渡す型スペックの文法と、コマンドラインの使い方をまとめる。
探索の進め方そのものは `skill/SKILL.md`、情報制約は `docs/observation_spec.md` /
`docs/observation_spec_v2.md` を参照。

## 1. 型スペックの文法

1行が1つの型を表す。フィールドは `|` 区切りで、末尾の特性フィールドは省略できる。

```
HP,攻撃,防御,特攻,特防,素早さ | 技,技,技,技 | 方針 | アイテム | メガ | 特性
```

例（run3 決勝1位の型）:

```
164,192,182,113,132,162|FS,IW,ST,EQ|obsh3|stone|1|cb
```

### 能力値（実数値）

- 6つの数値は **レベル50での実数値**（HP, 攻撃, 防御, 特攻, 特防, 素早さの順）。
  努力値にあたる「能力ポイント」ではないので注意すること。
- ポイント配分から実数値への換算: まずフォルムごとの基礎値（ポイント0・個体値31）に
  ポイント（各0〜32、合計66）を加え、最後に性格補正（上昇 ×110/100、下降 ×90/100、
  いずれも切り捨て）を掛ける。HP に性格補正は掛からない。

| フォルム | HP | 攻撃 | 防御 | 特攻 | 特防 | 素早さ |
|---|---|---|---|---|---|---|
| 通常 | 155 | 155 | 150 | 115 | 110 | 90 |
| メガ | 155 | 165 | 170 | 125 | 130 | 130 |

### 方針（操縦役）

対戦を操作する方針のトークン。**誰が操縦するかで型の評価は変わる**ため、結果には
必ず方針を併記すること。

| トークン | 内容 |
|---|---|
| mirror | ミラー用の単純ヒューリスティクス（検証マトリクスの既定） |
| noise | ランダム寄りの単純方針 |
| fast | 速攻寄りの単純方針 |
| stall | 耐久寄りの単純方針 |
| generic | 全情報ベースライン（相手の全情報を見て判断する。比較用と明示した場合のみ使う） |
| obsdemo | 観測 v1 の動作確認用デモ方針 |
| obsh2 | 観測 v1 のヒューリスティクス方針（17技用） |
| learned | 学習方針 g12（観測 v1・17技専用） |
| obsdemo2 | 観測 v2 の動作確認用デモ方針 |
| obsh3 | 観測 v2 のヒューリスティクス方針（68技・現行の標準） |
| learned2 | 学習方針（観測 v2。対照超えは未確認で、現行の操縦役ではない） |

観測系の方針（obsdemo / obsh2 / learned / obsdemo2 / obsh3 / learned2）同士の対戦では、
観測仕様に反する型（語彙外の技を含む等）はエラーで拒否される。v1 系と v2 系は混ぜられない。

### メガと特性

- メガフィールドは `1`（メガシンカ状態で対戦）か `0`。エンジンは対戦開始時から
  メガ状態として扱う（対戦中のメガシンカは未モデル化。`docs/known_issues.md` 参照）。
- 特性フィールドは通常フォルム用で `cb`（クリアボディ）か `lm`（ライトメタル）。
  メガ時は特性が かたいツメ に固定されるため、このフィールドは無視される。
- **特性フィールドを省略した型は旧形式として扱われる**。観測系方針の対戦では、
  旧形式の型を使うには環境変数 `ENGINE_OBS_COMPAT=1` が必要（検証マトリクスの
  再現用に用意された互換モード）。新規の型には特性フィールドまで書くこと。

### 未知のトークンへの警告

方針・アイテム・特性・技コードに未知のトークンを書くと、エンジンは標準エラーに
一度だけ警告を出し、既定値（方針=mirror、アイテム=none、特性=なし、技=無視）として
処理を続ける。タイポが静かに評価を変えることを防ぐための仕組みなので、警告が
出たらまずスペックを疑うこと。

## 2. CLI リファレンス

ビルドは `make verify`（または `gcc -O3 -march=native -o engine/engine engine/engine.c -lm`）。
以下、`<engine>` は `engine/engine` と読み替える。

| コマンド | 引数 | 出力 |
|---|---|---|
| `policy-version` | なし | 方針ごとの観測スキーマと重みハッシュ（1方針1行） |
| `matrix` | `[試合数] [シード]` | 検証マトリクス（既定 3000 / 12345）。MD5 が `engine/fixtures/expected_matrix_md5.txt` と一致することが導入セルフチェック |
| `battle` | `<型A> <型B> <試合数> <シード>` | 「A 勝ち数 - B 勝ち数（引分数）平均ターン数」 |
| `screen` | `<候補ファイル> <プールファイル> <試合数> <シード>` | 候補ごとに「番号 勝 敗 分」を1行ずつ（プール全員との合計） |
| `screenx` | `<候補ファイル> <プールファイル> <試合数> <シード>` | 候補ごとに「番号」に続けてプール1人ごとの「勝 敗 分」を1行で |
| `trace` | `<型A> <型B> <シード>` | 1試合の詳細ログ（全情報方針同士のみ。観測系方針では使えない） |

### 使い方の注意

- スコア規約は **勝 /（勝+敗+分）**。結果には常に対戦母集団・試合数・操縦方針・
  シードを併記すること。
- `screen` / `screenx` では候補は常に **A 席** に座る。席による差をならす必要がある
  評価（決勝など）では、候補とプールを入れ替えた実行も行い、両席を併せること。
- 平均勝率だけでなく **最悪相性**（プール内で最も低い相手別スコア）も必ず見ること。
  相手別の内訳は `screenx` で得られる（`screen` の合計だけでは最悪相性は分からない）。
- シードは試合ごとにハッシュで展開される決定的な規約で、同じ引数なら結果は再現する。
