# 種族別 1on1 探索（規模選択ツール）

任意の種族について、同種ミラー 1on1 の型探索を規模を選んで実行できます。  
候補生成（[search_tiers.py](search_tiers.py)）と、段階的絞り込み＋決勝総当たりの実行（[search_controller.py](search_controller.py)）が対になっています。操縦方針は観測 v3 のヒューリスティクス `obsh4` です。

## 使い方

```sh
# 1. 利用可能な規模と総試合数の一覧を確認
python3 search/search_tiers.py list

# 2. 候補と実行設定を生成（種族名は data/species_dataset.json のベース種族 ID）
python3 search/search_tiers.py gen gyarados standard runs/gyarados-std

# 3. 探索を実行（中断しても .done マーカーから再開可能）
python3 search/search_controller.py runs/gyarados-std --shards 10
```

- Windows では `python` ランチャや MinGW コンパイラパスに応じて `--gcc <path>` を指定できます（例：`--gcc gcc`）。
- 実行中は `[progress]` 行がコンソールに流れます（段階ごとの進捗・経過・ETA）。
- 出力は `runs/<名前>/finals_results.json` と `summary.json` に書き出されます。
  - `ranking`：決勝総当たりにおける A 席側スコア（自己ミラー含む）の順位表（後方互換）。
  - `ranking_both_seats`：同じ決勝結果から A/B 両席を合算し自己ミラーを除外した順位表。
  - 結果報告には必ず「種族・規模・操縦方針・試合数・絞り込み条件」を併記してください。
- 対応種族はエンジン実装済みの全 341 種族です（型スペックの文法は [docs/spec_and_cli.md](../docs/spec_and_cli.md)、実装時の設計詳細は [docs/archive/stage8_spec.md](../docs/archive/stage8_spec.md) を参照）。
- Web UI から種族・絞り込み条件を指定して探索を実行・分析する場合は [../viewer/server.py](../viewer/server.py) を起動します（`python3 viewer/server.py`）。

## 候補の絞り込み条件（部分領域探索）

`search_tiers.py gen` では、検証したい候補空間だけを明示的に狭めることができます。

- **絞り込み対象は候補側（`candidates.txt`）のみ**で、評価基準となる相手パネル（`panel.txt`）は常にその種族全体の無制約ドメインから抽選します。
- 定義 A（性格↓への無駄ポイント除外）・定義 B（最大 16 以下の均等配分除外）は絞り込み時も維持されます。
- 絞り込み後の合法な型数が目標候補数（`--candidates` または選択規模の上限）以下の場合は重複なしの**全列挙（`exhaustive`）**、上回る場合は**一様サンプリング（`sampled`）**を自動選択します。絞り込み条件と列挙方式は `candidates_meta.json`・`run_config.json`・`finals_results.json`・`summary.json` に記録されます。

主な絞り込みオプション（複数指定で OR、異なる種別間は AND）：

| オプション | 内容・指定例 |
|---|---|
| `--candidates N` | 生成候補数の上限を上書き（未指定時は選択規模どおり） |
| `--move <id>` | 採用候補の技プールを限定（複数回指定可） |
| `--require-move <id>` | 必須技（指定技はすべて採用・複数回指定可） |
| `--move-count 1..4` | 採用技数を指定（絞り込み有効時の既定は `4` のみ） |
| `--item <id>` | 持ち物を限定（`none` / どうぐ ID / メガストーン ID、複数回指定可） |
| `--mega 0\|1\|2` | メガ区分（`0`: 非メガ、`1`: メガ開始、`2`: 通常開始＋任意メガ） |
| `--ability <id>` | 特性を限定（複数回指定可） |
| `--sex m\|f\|n` | 性別を限定 |
| `--nature up,down` | 性格を限定（例: `1,3` いじっぱり、`0,0` 無補正、複数回指定可） |
| `--stat-min H,A,B,C,D,S` / `--stat-max ...` | 各能力のポイント下限・上限（0〜32、合計 66 の全配分から自動抽出） |
| `--allocation H,A,B,C,D,S` | 固定のポイント配分を直接指定（0〜32・合計 66、複数回指定可） |

`--stat-min`/`--stat-max` の上下限は、定義 A/B 除外後の配分列挙だけでなく Web UI からも設定できます。

## 規模の目安

所要時間は CPU 性能にほぼ比例します。下表はデスクトップ級（Core i5-12400、10 並列）での実測・推定で、小さな VM では概ね 10 倍ほどかかります。**まず軽量で回し、必要なら標準に上げるのが基本です。**

| 規模 | 候補数 | 総試合数（概算） | 所要時間の目安（デスクトップ級） |
|---|---|---|---|
| `light`（軽量） | 60,000 | 約 408 万 | 約 7 分 |
| `standard`（標準） | 200,000 | 約 2,134 万 | 約 46 分（ギャラドスで実測） |
| `precision`（精密） | 500,000 | 約 1.34 億 | 約 3.5 時間 |

- 1 時間程度で終わらせたい場合は `standard` までが現実的な上限です。
- `precision` は `run3`（メタグロス 68 技探索）と同規模の本格探索です。
- `smoke`（2,000 候補・約 1.9 万試合）は動作確認専用の最小構成です。

## 探索の規約

- 候補の削減は「数学的に同一な型」と「数学的に劣る型」（性格↓能力への無駄ポイント、全能力 16 以下の均等型）だけです（[population3.py](population3.py) / [population3_catalog.c](population3_catalog.c)）。役割の想定で候補を切ることはしません（[skill/SKILL.md](../skill/SKILL.md)）。
- 評価は平均勝率と最悪相性の両方を見ます。1on1 には三すくみ構造があり得るため、「単一の最強」を主張せず、母集団を明示して報告します。

## メガシンカのタイミングについて（検証手順）

標準の前提は「1 ターン目にメガシンカする」です。これはメタグロスとギャラドスで実測により裏付けられています（遅らせた場合の固定ターン比較では全層で大幅に悪化し、完全情報オラクルによる上限測定でも得は確認できませんでした）。

別の種族でタイミングが問題になりそうな場合は、次の手順で別途検証してください（全種族への一律の先回り検証はしません）。

1. **机上チェック**：メガ前後のフォルム差（タイプ相性・特性・能力）を決勝プールの技構成と突き合わせ、「相手の技で得失が反転する組み合わせ」が実際に存在するかを確認する。存在しなければ即メガで確定。
2. **上限の測定**：反転が存在する場合、その反転に連動する完全情報オラクル（相手の選択した技を見てから遅延を決める上限）で測る。
3. **線引き**：上限が即メガ比で **+3 ポイント（100 戦で 3 勝分）** に届かなければ、タイミング方針は作らず即メガを標準とする。届いた場合のみ、実情報で動く方針の実装を検討する。
