# 種族別 1on1 探索（規模が選べます）

任意の種族について、同種ミラー1on1の型探索を規模を選んで実行できます。
候補の生成（`search_tiers.py`）と、段階的絞り込み＋決勝総当たりの実行
（`search_controller.py`）が対になっています。操縦役は両者とも観測v3の
ヒューリスティクス方針 `obsh4` です。

## 使い方

```sh
# 1. 候補と実行設定を生成する（種族名は data/species_dataset.json の英語名）
python3 search/search_tiers.py gen gyarados standard runs/gyarados-std

# 2. 探索を実行する（中断しても .done マーカーから再開できます）
python3 search/search_controller.py runs/gyarados-std
```

- 実行中は `[progress]` 行がコンソールに流れます（段階ごとの進捗・経過・ETA）。
- 結果は `runs/<名前>/finals_results.json`（決勝の型・順位・相性行列）と
  `summary.json` に出ます。結果には必ず「種族・規模・操縦方針・試合数」を
  併記してください（母集団を明示しない勝率は意味を持ちません）。
- 対応種族はエンジン実装済みの全341種族です（各種族の習得技・特性・
  持ち物・メガシンカは `docs/stage8_spec.md` を参照）。

## 規模の目安

所要時間はCPU性能にほぼ比例します。下表の時間はデスクトップ級
（Core i5-12400、10並列）の実測・推定で、小さなVMでは概ね10倍ほど
かかります。**まず軽量で回し、必要なら標準に上げるのがおすすめです。**

| 規模 | 候補数 | 総試合数（概算） | 所要時間の目安（デスクトップ級） |
|---|---|---|---|
| 軽量 light | 60,000 | 約408万 | 約7分 |
| 標準 standard | 200,000 | 約2,134万 | 約46分（ギャラドスで実測） |
| 精密 precision | 500,000 | 約1.34億 | 約3.5時間 |

- 1時間程度で終わらせたい場合は、標準までが現実的な上限です。
- 精密は run3（メタグロス68技探索）と同規模の本格探索です。
- `smoke` は開発用の最小構成（約1.9万試合）で、動作確認専用です。

## 探索の規約

- 候補の削減は「数学的に同一な型」と「数学的に劣る型」（性格↓能力への
  無駄ポイント、全能力16以下の均等型）だけです。役割の想定で候補を
  切ることはしません（`skill/SKILL.md` の手順に従います）。
- 評価は平均勝率と最悪相性の両方を見ます。1on1には三すくみ構造が
  あり得るため、「単一の最強」を主張せず、母集団を明示して報告します。

## メガシンカのタイミングについて（検証手順）

標準の前提は「1ターン目にメガシンカする」です。これはメタグロスと
ギャラドスで実測により裏付けられています（遅らせた場合の固定ターン
比較では全層で大幅に悪化し、完全情報オラクルによる上限測定でも
得は確認できませんでした）。

種族ごとに事情が違うため、別の種族でタイミングが問題になりそうな
場合は、次の手順で別途検証してください。全種族に一律の先回り検証は
しません。

1. **机上チェック**: メガ前後のフォルム差（タイプ相性・特性・能力）を
   決勝プールの技構成と突き合わせ、「相手の技で得失が反転する組み合わせ」
   が実際に存在するかを確認する。存在しなければ即メガで確定。
2. **上限の測定**: 反転が存在する場合、その反転に連動する完全情報
   オラクル（相手の選択した技を見てから遅延を決める上限）で測る。
3. **線引き**: 上限が即メガ比で **+3ポイント（100戦で3勝分）** に
   届かなければ、タイミング方針は作らず即メガを標準とする。
   届いた場合のみ、実情報で動く方針の実装を検討する。
