# 学習パイプライン

自己対戦による方針／価値ネットワークの学習一式。軌跡生成はCPU（エンジン）、
学習はGPU（PyTorch）を想定し、生成と学習は分離されている。

## 構成
- `data.py` / `model.py`： 軌跡フォーマット（FORMAT.md）とネットワーク定義、
  重みのCヘッダ書き出し。
- `train.py`： PPO学習本体。
- `prepare.py` / `verify.py` / `parity.py`： 準備と検証（推論のパリティ確認）。
- `campaign_local.py`： 生成→学習→書き出し→評価をローカルで回す参照
  コントローラ。元の開発では学習レグを別PCのGPUで実行していたため、
  リモート実行したい場合は学習ステップだけを Colab / Modal 等へ切り出す。
- `build_heldout.py` / `analyze.py` / `manifest.py`： 保留評価用プールの
  構築と集計。

## 依存
Python 3、NumPy、PyTorch（`requirements.txt`）。

## 注意
- 学習の評価は必ず未見の型（保留プール）で行い、訓練母集団での結果と
  区別して報告すること。
- 方針の事前分布（ヒューリスティクスの重み付け）を弱める過程では、
  決定論評価が事前分布から動くかどうかを世代ごとに確認すること。

## レイアウト注記
各モジュールは開発時の配置（stage3/）を前提とした相対パスを含む。配布では training/ に平置きしているため、実行時はパスを読み替えること。
